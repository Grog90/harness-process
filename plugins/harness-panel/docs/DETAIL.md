# harness-panel

## Что это

Две поверхности:

1. **Компактная панель** в `conversation.composer.dock`: live-сводка, последние
   change, активные задачи, кнопка «открыть доску».
2. **Полная доска** в слоте `main` с ключом `harness-board`: KPI, очередь, фильтры
   `Активные / READY / Блок / Архив / Все`, поиск, список change и задач.

Кнопка «открыть доску» вызывает `ctx.layout.selectPanel('harness-board')`.
Если слот `main` недоступен, компактная панель продолжает работать.

## Данные

Клиент запрашивает same-origin `/harness-panel/metrics.json`; host-часть
проксирует к `http://127.0.0.1:8765/metrics.json`. Адрес доски для host-части —
`HARNESS_BOARD_URL`; клиентского override нет.

Без запущенной доски обе поверхности показывают `offline` и команду запуска.
Это read-only вид: гейты и приёмка остаются в harness, панель ничего не меняет.

## Перезапуск

Client-плагин загружается при старте DSH; после установки/обновления бандла
нужен перезапуск приложения, HMR для этого бандла не гарантирован.
