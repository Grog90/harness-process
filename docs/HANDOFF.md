## Что сломано/непонятно

1. **Слева в DSH нет пункта «доска»** — его никто не делал. В плагине были
   только compact-панель в композере и main-слот `harness-board`, который
   открывается кнопкой «открыть доску». Если кнопки не видно — плагин не
   загрузился в текущем профиле.
2. **Доска «всегда offline»** — это compact-панель, а не сама доска. Панель
   ходит на `/harness-panel/metrics.json`; host-часть проксирует
   `http://127.0.0.1:8765/metrics.json`. Если процесс `harness board` не
   запущен — она честно показывает offline. После рестарта DSH процесс
   умирает; его надо запускать снова.
3. **Плагин после рестарта не появился** — client-бандл DSH требует
   перезапуска/переустановки, но в текущем профиле панель не отрисовалась.
   Не добавлять новые фичи, пока не выяснено: bundle в профиле есть
   (`@local/harness-panel` в `package.json`), но client-слот не виден.
4. **Ощущение «криво»** — потому что смешаны три вещи: отдельная HTML-доска,
   compact-панель в композере и main-доска. Их надо развести.

## Решение на следующий чат (простое)

Не делать ещё одну UI-революцию. Сначала стабилизировать:

1. Запустить `python -m harness board --serve --port 8765`.
2. Открыть `http://127.0.0.1:8765/` — убедиться, что HTML-доска живая.
3. Только потом решать, нужен ли плагин. Если нужен — один пункт слева,
   один экран, без compact+main одновременно.
4. Если плагин не грузится — смотреть `~/.dsh/profiles/desktop/package.json`,
   `.plugin-manager/logs`, консоль DSH; не маскировать ошибку `try/catch`.

## Память

- DSH хранит сессии локально в `~/.dsh/sessions/`; новый чат их **не читает
  автоматически**.
- В проекте есть `tools/recall.py`:
  - `python tools/recall.py index` — индексировать прошлые сессии;
  - `python tools/recall.py search "доска"` — найти обсуждение.
- Этот файл — детерминированный handoff: новый чат должен прочитать его, а не
  полагаться на «память».
