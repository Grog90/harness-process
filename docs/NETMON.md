# netmon — панель обращений и ошибок

Заменяет связку Prometheus + Grafana (та жила на старом VPS, который выведен из строя).
Одна страница, ~30 МБ памяти, ничего не перехватывает на роутере.

**Адрес:** http://91.103.253.94:8080 (без пароля, открыт наружу по решению владельца)

## Откуда данные

| Источник | Что даёт |
|---|---|
| `GET :2222/api/connections` | устройство, адресат, порт, протокол, состояние, байты, туннель |
| `GET :2222/api/logs?level=warn` | сообщения AWG Manager (маршрутизация, NDMS) |
| `journalctl -u hysteria-server` | сетевые ошибки Hysteria: таймауты, обрывы, отмены потоков |
| `http://127.0.0.1:9115/probe` | коды HTTP по пробам: Telegram, Google (VPN и напрямую) |

Роутер отдаёт снимок соединений и логи; панель сама считает ошибки и историю.
`2222` и `9115` проброшены с роутера обратным SSH-туннелем (пользователь `tunnel`,
только port-forwarding).

## Что считается ошибкой

- **connect** — соединение провисело в `SYN_SENT` три опроса подряд (≈15 с) и не установилось.
- **hysteria** — строки с `"error"` из журнала сервера (dial timeout, stream canceled,
  client disconnected).
- **awgm** — предупреждения AWG Manager.

Повторы сворачиваются: одна строка с `×N` вместо сотни одинаковых.
Локальные адреса (10.x, 192.168.x) вынесены в отдельный блок «Локальный шум» —
это не интернет и в ошибки не попадает.

## Файлы

| Где | Что |
|---|---|
| `/home/deploy/netmon/netmon.py` | сам сервис (stdlib, без зависимостей) |
| `/etc/systemd/system/netmon.service` | unit, `MemoryMax=200M` |
| роутер: `/opt/var/monitoring/tunnel_loop.sh` | туннель на новый VPS |

Перезапуск: `sudo systemctl restart netmon`, логи: `journalctl -u netmon -f`.

## Чего панель не показывает и не покажет

- **URL запросов** — трафик зашифрован TLS; видны адресат и сервис по подсети.
- **Коды ответов твоих собственных запросов** — только у синтетических проб
  (Telegram/Google), потому что свои запросы роутер видит лишь как IP:порт.
- **Здоровье Instagram синтетикой не меряется сознательно.** Проба раз в 30 с —
  это 2880 запросов в сутки с IP VPS и прямой путь к `429` и бану адреса.
  Instagram читается только пассивно: соединения к его подсетям (есть ли, сколько
  байт, QUIC или TCP, не завис ли `SYN_SENT`) и ошибки Hysteria с `reqAddr` в
  этих подсетях. Цена честности: код ответа Instagram отсюда не виден.
- **Имена сайтов** без DNS-лога. Единственный безопасный способ их получить —
  AdGuard Home как DNS для домашней сети (без захвата пакетов).

## Почему не ntopng

ntopng 6.6 из Entware ставится на флешку и запускается, но захват пакетов на `br0`
укладывает этот роутер: AWG Manager и веб-интерфейс Keenetic перестают отвечать,
хотя интернет и пинг работают. Восстановление — убить ntopng и redis, после чего
службы оживают. Автозапуск ntopng из `S99monitoring` убран навсегда.
