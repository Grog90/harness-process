# Уроки: как ошибка превращается в ограничение

Документ описывает процесс, а не набор советов. Цель — не «запомнить ошибку», а сделать её
повторение либо невозможным, либо мгновенно заметным.

Текст в инструкции модель может проигнорировать, особенно после компакции контекста.
Поэтому у каждого урока есть ступень, и текст — только вторая из трёх.

## Лестница

| Ступень | Триггер перехода | Артефакт | Проверка | Цена |
|---|---|---|---|---|
| 1. Случай | произошло впервые | запись в `journal/YYYY-MM.md` | нет | ноль (не в контексте) |
| 2. Правило | повторилось дважды | строка в `AGENTS.md`, раздел «Уроки» | `tools/lessons.py check` | токены в каждом запросе |
| 3. Автоматика | правило нарушено ещё раз | правило в `policies/rules.json` + тест | `harness coverage`, `selftest` | код и поддержка |

Критерий ступени 3: если нарушение **ловится детерминированно** — есть вход, есть
однозначный ответ, и ответ не зависит от суждения проверяющего, — то текст правила не
решение: нужен тест или хук. Абзац в стандартах лечит только то, что нельзя проверить
машиной.

Ключевое ограничение: **в `AGENTS.md` попадает только ступень 2**, и только подтверждённая
повтором. Файл на 300 строк уроков оплачивается в каждом запросе и размывает внимание модели
до состояния, когда не работает ни одно правило. Бюджет раздела — 25 строк, проверяется
командой `check`.

## Дважды — почему два

Одна попытка — норма: агент не знал среды. Две подряд с одним и тем же симптомом — паттерн.
Три — уже статистика, и это сигнал, что текст не работает: нужна ступень 3.

## Формат записи

Запись создаётся командой, а не руками, чтобы поля не разъезжались:

```powershell
python tools/lessons.py new `
  --slug "pwsh + кириллица в пути" `
  --type среда `
  --trigger "команда в PowerShell, путь содержит не-ASCII или пробелы" `
  --symptom "не удаётся найти путь; файл создан не там" `
  --cause "cd и конкатенация строк ломаются на спецсимволах" `
  --rule "всегда -LiteralPath и кавычки; рабочую папку задавать параметром, не через cd" `
  --scope "Windows" `
  --tried "cd в кавычках; Join-Path без -LiteralPath"
```

Обязательны: `--trigger`, `--symptom`, `--rule`, `--type`, `--scope`. Причина (`--cause`)
и список несработавших попыток (`--tried`) не обязательны формально, но именно они чаще всего
спасают: агент склонен повторять мёртвый подход, а не только ошибку.

Поле `Триггер` — самое важное. Модель не применяет «учитывай особенности Windows»; она
применяет «когда путь содержит не-ASCII — `-LiteralPath`». Правило без триггера не срабатывает.

## Типы ошибок и их дома

| Тип | Пример | Куда | Почему туда |
|---|---|---|---|
| `среда` | «тесты через pnpm, не npm»; «кириллица ломает cd» | `AGENTS.md`, раздел правил | действует всегда, стоит один раз |
| `домен` | «эндпоинт требует заголовок X» | `docs/` + указатель в `AGENTS.md` | нужно только при работе с этой областью |
| `поведение` | «не запустил тесты», «догадался вместо чтения» | ступень 3 | текстом не лечится, лечится проверкой |

Если ошибка типа `поведение` повторилась — не писать третий раз «будь внимательнее». Это
заявка на хук или тест.

## Продвижение

```powershell
python tools/lessons.py list                 # все записи и их состояние
python tools/lessons.py scan                 # кандидаты: повторилось >= 2 раз
python tools/lessons.py promote L-20261026-01            # показать diff для AGENTS.md
python tools/lessons.py promote L-20261026-01 --apply    # вставить после маркера
python tools/lessons.py promote L-20261026-01 --shape json  # заготовка для rules.json
```

`--shape json` печатает объект в форме `policies/rules.json` с `"implemented": false`:
он сразу виден в `harness coverage` как заявленный пробел. Это и есть ступень 3 —
правило не «есть», пока у него нет исполняемой проверки.

Изменение `rules.json` — только через `python -m harness rule change --id ... --reason "..."`,
иначе `rule verify` зафиксирует расхождение отпечатка (R-HOOK-1).

## Курирование

- **Раз в неделю, 10 минут:** пройтись по разделу «Уроки» в `AGENTS.md`. Правило не сработало
  ни разу — в `docs/pitfalls/`. Правило нарушено после добавления — на ступень 3.
- **Одно правило — одно место.** Дубликаты ловит `check` (сравнение по пересечению слов),
  но лучше не доводить.
- **Не хранить то, что устареет:** версии, имена веток, «сейчас переезжаем на X». Это lockfile
  и issue, не память агента.
- **Секретов в журнале нет.** Токены и пути к кредам просачиваются в такие файлы постоянно;
  запись с `token`, `password`, `secret` в тексте `check` помечает как ошибку.

## Противоречия

Две записи могут дать несовместимые правила. Разрешение — не компромисс, а явное решение:
более новое правило побеждает, старое удаляется или сужается по `--scope`. Если сузить нельзя —
значит, правило сформулировано неверно.

## Метрики

Смысл процесса — не количество уроков, а два числа:

1. **Размер раздела «Уроки».** Растёт — не курируете.
2. **Доля повторов.** Одна и та же ошибка случилась второй раз после ступени 2 — значит,
   ступень 2 не сработала; сразу на ступень 3.

Хороший признак: `AGENTS.md` почти не растёт, а `tests/` и `selftest` растут.

## Чего этот процесс не делает

- Не работает для агентов, которые не читают `AGENTS.md`.
- Не заменяет `selftest`: текст можно нарушить молча, тест — нет.
- Не ловит ошибки, которые никто не заметил: журнал пишет тот, кто упёрся, а не тот, кто прав.
- Не хранит контекст сессий: транскрипты лежат отдельно (`~/.dsh/sessions/*.zstd`), это
  другой механизм и другая задача.
