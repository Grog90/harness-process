# XERJ: локальный поиск по коду и докам

Подключено 27.10.2026. xerj v1.0.0-rc.99, Apache-2.0, один Rust-бинарник.
Здесь: зачем он, как поставлен, чем отличается от Hindsight и recall, где границы.

## 1. Зачем

`recall.py` ищет дословно по истории сессий, Hindsight хранит атомарные факты.
Ни то, ни другое не отвечает на вопрос «покажи, где в коде/доках это сделано» —
приходится читать файлы целиком. xerj индексирует папку (код через tree-sitter,
доки, JSONL/CSV, PDF, логи) и отдаёт **пассаж с `file:line`**, а не файл.

Дополнительно он умеет то, чего у нас нет: индекс как ES-совместимый API
(`localhost:9200`), `xerj def` (переход к определению), гибридный поиск и
`/_memory` — память агента по смыслу.

## 2. Установка

```powershell
# бинарник — из релиза, с проверкой sha256 (не через irm | iex)
Invoke-WebRequest https://github.com/xerj-org/xerj/releases/download/v1.0.0-rc.99/xerj-1.0.0-rc.99-x86_64-pc-windows-msvc.zip -OutFile xerj.zip
(Get-FileHash xerj.zip -Algorithm SHA256).Hash   # 6e3e4b89…dd47e
```

Распакован в `.tools/xerj/pkg/` (`.tools/` в `.gitignore`), 128.7 МБ, версия
`xerj v1.0.0-rc.99`.

### Почему каталоги данных пришлось помечать как Low integrity

Первые запуски падали: `failed to open node lock … Отказано в доступе (os error 5)`,
и даже `create data dir` не проходил. Проверка показала: **неподписанные сторонние
бинарники в этой системе стартуют на низком уровне целостности** — им разрешено
читать, но не создавать файлы в обычных каталогах. Подписанный `python.exe`,
запущенный из того же шелла, писал туда же без проблем; `moli.exe` (тоже
неподписанный Rust) падал так же.

Лечится не отключением защиты, а пометкой каталогов, куда пишет бинарник:

```powershell
icacls "C:\Users\ownag\.xerj-data" /setintegritylevel "(OI)(CI)L"   # данные ноды
icacls "C:\Users\ownag\.xerj"      /setintegritylevel "(OI)(CI)L"   # состояние autoindex
```

После этого нода поднимается за ~1 с и отвечает как Elasticsearch 8.13.

## 3. Запуск и индексация

```powershell
xerj.exe --insecure --data-dir C:\Users\ownag\.xerj-data      # нода, 127.0.0.1:9200
xerj.exe autoindex . --prefix harness                          # рабочая папка
```

Нода живёт отдельной задачей планировщика **`xerj-node`** (триггер — вход в систему),
поэтому переживает перезапуск приложения и сессии. `--insecure` = без TLS и ключа,
только на loopback: один пользователь на машине, для локального поиска этого достаточно.

Первый индекс: 120 файлов, 1434 записи, 3 датасета, 12.5 с. Что не индексируется —
`.xerjignore` (мусор прошлых экспериментов: `probe_*`, `pip-*`, `torchinductor_Grog`)
плюс встроенные правила: dot-каталоги (`.tools`, `.browser`, `.hindsight`, `.recall`,
`.harness`) и `.gitignore`.

## 4. Подключение к DSH

`~/.dsh/profiles/desktop/cordis.patch.yml`, блок `- insert:` (не верхний уровень —
там только оверрайды по id):

```yaml
    - id: mcp-xerj
      name: '@deepseek-ai/dsh-mcp-client'
      config:
        serverName: xerj
        transport: stdio
        command: '...\tools\xerj\pkg\xerj-1.0.0-rc.99-x86_64-pc-windows-msvc\xerj.exe'
        args: [mcp]
        env:
          XERJ_URL: 'http://localhost:9200'
          XERJ_DISABLE_FEEDBACK: 'true'
```

`XERJ_DISABLE_FEEDBACK` обязателен: xerj по умолчанию **сам** отправляет отчёт об
использовании (PR на GitHub или POST на xerj.org). В README это подано как «no need
to ask the user» — для нас это внешняя отправка без спроса, поэтому выключено.

Инструменты у модели: `xerj_search`, `xerj_def`, `xerj_semantic_search`,
`xerj_hybrid_search`, `xerj_map`, `xerj_index_budget`, `xerj_memory_*`,
`xerj_code_search` и ещё десяток.

## 5. Чем отличается от того, что уже есть

| | xerj | Hindsight | recall.py |
|---|---|---|---|
| Хранит | файлы как есть, AST-разметка | факты-атомы + граф связей | сообщения сессий |
| Как попадает | парсинг файлов, без LLM | LLM извлекает факты из текста | zstd → SQLite FTS |
| Отвечает | «где это написано» (пассаж, `file:line`) | «что мы знаем» (синтез) | «где это сказано» (дословно) |
| Цена записи | 0 токенов | 3–4 тыс. токенов на 1 КБ | 0 |
| Когда врёт | не врёт, но промахивается по смыслу | может обобщить неверно | не обобщает вовсе |

Пересечение одно — `/_memory` у xerj и есть Hindsight. Держать два реестра фактов
нельзя: договорились, что **Hindsight остаётся реестром решений**, а xerj — поиском
по корпусам. Проверять это надо на одном бенчмарке (см. ниже), а не на глаз.

## 6. Границы

* Поиск лексический (BM25) по умолчанию; «семантика» без нейросетевого эмбеддера —
  это хеширование признаков, а не смысл. Промахи по перефразировке ожидаемы.
* Смешанный корпус: код перебивает прозу на общих словах. Лечится фильтром по
  `ax_format` (`code`, `txt-prose`, `yaml`, …).
* Нода должна быть запущена: `xerj mcp` только проксирует HTTP, сам он не поднимает
  сервер. Нет ноды — инструменты отвечают ошибкой, а не пустым списком.
* `.xerjignore` не поднимает dot-каталоги: секреты и `.env` остаются вне индекса
  по отдельному правилу, и это правильно.

## 7. Замер: xerj против Hindsight на одних и тех же вопросах

Метод: 15 атомарных фактов из `tools/memory_facts_bench.py` выложены отдельными
файлами (`C:\Users\ownag\.xerj-bench\facts\F01.md` … `F15.md`), проиндексированы
как префикс `facts`; вопросы — те же 10, что в бенчмарке, попадание считается по
опорному слову из него. Hindsight получал те же 15 фактов (банк `facts`), поиск —
`prefer_observations: false`.

| Корпус | hit@1 | hit@3 |
|---|---|---|
| xerj, 15 фактов (префикс `facts`) | **9/10** | **9/10** |
| Hindsight, те же 15 фактов | **9/10** | **9/10** |
| xerj, весь репозиторий (120 файлов) | 4/10 | 6/10 |
| xerj, курируемая область (`docs/FACTS.md` + `AGENTS.md` + `journal/`) | 5/10 | 7/10 |
| xerj, три перефразировки вопроса | 3/3 | 3/3 |

Оба промаха на `Q2` («почему нельзя писать в системный TEMP?») совпадают: ни в
одном факте нет слова «TEMP», есть «вне корня воркспейса» и `R-PROT-1`. Это промах
формулировки, а не движка — и он одинаковый у обоих.

**Что следует.**

1. На атомарных фактах xerj **не хуже** Hindsight при нулевой цене записи и
   задержке ~10 мс против ~1 с. Как хранилище фактов Hindsight больше не нужен.
2. На живом репозитории BM25 заметно слабее (6/10): код перебивает прозу, а
   нужная фраза часто лежит в другом разделе документа. Лечится **областью
   поиска** — фильтром по `ax_path`/`ax_format`, а не сменой движка.
3. Курируемая область лучше целого репозитория (7/10 против 6/10) даже на таком
   маленьком срезе. Практическое правило: вопрос «что мы знаем» — искать в
   `docs/FACTS.md` + `journal/` + `AGENTS.md`; вопрос «где это в коде» — по всему
   индексу.
4. Hindsight остаётся только там, где ценен граф связей и UI. Если и это не нужно —
   контейнер можно гасить, источником правды становится `docs/FACTS.md`.

**Решение (27.10.2026): Hindsight свёрнут.** Основание — паритет на фактах при
нулевой цене записи. Что сделано:

```powershell
Disable-ScheduledTask -TaskName "hindsight-autostart"   # не удалена — обратимо
Disable-ScheduledTask -TaskName "harness-push-facts"
docker update --restart=no hindsight
docker stop hindsight
```

Контейнер и том `hindsight-data` **не удалены**: данные лежат, вернуть можно
`docker start hindsight` + `Enable-ScheduledTask`. Код `tools/push_facts.py`,
`tools/memory_compare.py`, `tools/memory_facts_bench.py` оставлен как история
эксперимента и как измерительный инструмент — он работает против любого сервиса,
который поднимут снова.
