# Trendshift: тренды GitHub как источник и как инструмент

Проверено 26.10.2026 на живом сервисе. Здесь три вещи: как устроен доступ к данным,
что мы из него сделали (`tools/trendshift.py` + MCP-сервер) и что из трендов стоит
взять в наш контур, а что нет.

---

## 1. Как устроен доступ

Публичного API у trendshift.io **нет**. Проверены и не существуют: `/api/trending`,
`/api/repositories`, `api.trendshift.io/v1/trending`, `/rss`, `/feed.xml`. Есть только
`/sitemap.xml` (карта страниц) и несколько внутренних маршрутов UI.

Что есть на самом деле:

| Маршрут | Что отдаёт | Пригодность |
|---|---|---|
| `/`, `/weekly`, `/monthly`, `/yearly` | топ-25 за период | **основной источник** |
| `/api/social-mentions/latest` | живые упоминания (X, HN, Reddit) с `repository_full_name` | бонус: «почему растёт» |
| `/api/search?q=` | поиск | 403 без сессии — не используем |
| `/api/badge/repositories/<id>` | SVG-бейдж | картинка, не данные |

Данные лежат в RSC-потоке Next.js: страница содержит
`self.__next_f.push([1, "<экранированный JSON>"])`, внутри — `initialData` с массивом
записей. Оттуда и берём: распаковываем JS-строку через `json.loads`, склеиваем куски
потока, вытаскиваем `initialData` балансировкой скобок с учётом строк.

Что важно знать про данные:

* **25 записей на период**, пагинации нет: `?page=2` отдаёт ту же первую страницу.
  Это не «весь GitHub», а верхушка — для мониторинга этого достаточно, для
  статистики нет.
* Прирост (`stars_gained`) считается **за период страницы**: у monthly это месяц,
  у yearly — год, поэтому числа между периодами несравнимы напрямую.
* `repository_created_at` есть у всех записей — возраст считается локально.
* Разметка может измениться в любой момент. Ломается разбор — падает
  `TrendshiftError`, а не тихо пустой список.

## 2. Что сделано

```
tools/trendshift.py       — сбор, снапшоты, дифф, дайджест (stdlib, без зависимостей)
tools/trendshift_mcp.py   — MCP-сервер поверх него (stdio, JSON-RPC)
tests/test_trendshift.py  — 30 проверок: разбор, дифф, хранилище, протокол
```

### CLI

```powershell
python tools/trendshift.py top --period daily --limit 15            # срез
python tools/trendshift.py top --period weekly --ai-only            # только ИИ-тематика
python tools/trendshift.py digest --limit 10                         # сводка по 4 периодам
python tools/trendshift.py watch --ai-only                           # снапшот + только изменения
python tools/trendshift.py diff --period daily                       # два последних снапшота
python tools/trendshift.py history                                   # что в хранилище
```

Фильтры: `--ai-only` (эвристика по описанию/тегам/языку), `--language`, `--keyword`,
`--min-gain`, `--limit`. Вывод — текст, `--json` — машинный.

Хранилище: `~/.trendshift/snapshots/<period>/<UTC>.json` (переопределяется
`TRENDSHIFT_HOME`). Вне репозитория — это состояние, а не исходники. Дифф считается
между двумя последними снапшотами периода: пришли/ушли/насколько сдвинулись.

### MCP-сервер

Инструменты для модели (после подключения видны как `mcp__trendshift__*`):

| Инструмент | Что делает |
|---|---|
| `trending` | топ за период, фильтры, markdown-таблица |
| `digest` | все четыре периода одним ответом |
| `new_since_last` | снапшот + только вошедшие с прошлого запуска + скачки |
| `repository` | карточка `owner/name`: в каких периодах, с какими цифрами |

Подключение — запись в `~/.dsh/profiles/<profile>/cordis.patch.yml`:

```yaml
- id: mcp-trendshift
  name: '@deepseek-ai/dsh-mcp-client'
  config:
    serverName: trendshift
    transport: stdio
    command: 'C:\...\python.exe'
    args: ['C:\...\tools\trendshift_mcp.py']
    cwd: 'C:\...\default-workspace'
    toolCallTimeoutMs: 90000
```

Применяется после перезапуска приложения. До перезапуска работает CLI.

### Расписание

В сессии заведено напоминание «Trendshift: новые репозитории в топе» — ежедневно
09:00 Europe/Moscow, команда `watch --ai-only --limit 8 --jump 3`. Оно живёт в сессии
и срабатывает, когда приложение открыто.

Чтобы снапшоты копились и при закрытом приложении, нужна задача планировщика
Windows (не создана — это изменение системы, решать вам):

```powershell
schtasks /Create /SC DAILY /ST 08:50 /TN "trendshift-snapshot" /TR "pythonw.exe C:\...\tools\trendshift.py watch --quiet" /F
```

## 3. Что популярно сейчас

Срез 26.10.2026, trendshift.io, 25 позиций на период. Дальше — только про то, что
имеет отношение к агентной разработке.

### Год: сформировался жанр «агентный harness»

|---|---|---|---|
| 1 | `openclaw/openclaw` | +398k | агент «который реально делает», любая ОС |
| 2 | `obra/superpowers` | +294k | фреймворк агентных скиллов + методология разработки |
| 3 | `NousResearch/hermes-agent` | +258k | агент с памятью и ростом |

| 6 | `mattpocock/skills` | +302k | скиллы как файлы, из личного `.agents` |

Читается так: **год прошёл под знаком «скиллы + память + harness», а не «ещё один
чат»**. Мы в этом тренде, но с другой стороны: у нас процесс (бриф, вердикт, бюджет
попыток), у них — упаковка знаний (скиллы, память, инстинкты).

### Месяц: MCP стал нормой, скиллы — товаром

* `xerj-org/xerj` (+13.7k) — локальный поисковик **и MCP-сервер** для агентов;
* `lexmount/moli` (+18.2k) — headless-браузер для агентов;
* `ifixai-ai/iFixAi` (+17.4k) — аудит ИИ-агентов (человеком или самим агентом);

  с **независимо проверяемыми машиночитаемыми находками**;
* `yetone/magpie` (+18.6k) — «модель на агента», Codex на DeepSeek, Claude Code на Kimi;
* `Ebony-Vinyl/dsh-our-free-model` (+43.9k) — плагин к DSH с бесплатными моделями:
  пример того, как нас распространяют.

### Неделя и сутки: дизайн-скиллы и «убери рекламу»

Сутки возглавляют `Nutlope/hallmark` («anti-AI-slop» дизайн-скилл), `elayadesign/ai-design-skills`,

(`cleanyourtv`, `android-ad-cleaner`), которые взлетают волной, а не трендом.
Вывод: **скилл как единица поставки** — сейчас самый дешёвый способ упаковать
экспертизу; и это же — самый шумный сегмент.

## 4. Что взять себе, а что нет

Оценка по нашему контуру (бриф → роли → верификатор → вердикт-объект → бюджет попыток).
Половина «наших» механизмов уже есть в рантайме — см. [`PLUGINS.md`](PLUGINS.md);
здесь только то, чего у нас нет.

### Смотреть в первую очередь

| Источник | Что взять | Почему нам |
|---|---|---|
| `affaan-m/ECC` | структура «harness performance»: инстинкты, память, research-first | прямой аналог нашего слоя; сравнить, где мы переусложнили |
| `cloudflare/security-audit-skill` | формат находки: фаза → проверяемая находка → доказательство | наш вердикт-объект уже такой; сверить поля и строгость |
| `google/elephant-goldfish-model` | spec-driven development | бриф — это и есть спека; посмотреть, как у них оформлен вход |
| `thedotmack/claude-mem` | сжатие сессии в память | у нас `tools/recall.py` индексирует, но не сжимает; сравнить с `docs/RECALL.md` |
| `anthropics/skills`, `mattpocock/skills` | раскладка скилла (SKILL.md + ресурсы) | наш `plugins/` — код; скиллы — знания. Разные слои, оба нужны |
| `xerj-org/xerj` | MCP-сервер локального поиска | показывает, как MCP отдаёт поиск с ранжированием, а не список файлов |

### Не брать

* `openclaw`, `hermes-agent`, `cindy`, `rea` — продуктовые агенты целиком: своя
  архитектура, свои допущения; нам нечего переносить кроме идей.
* дизайн-скиллы и «убери рекламу с телевизора» — популярно, к пайплайну не относится.
* `dsh-our-free-model` — бесплатные модели через плагин: вопрос доверия и ключей,
  а не архитектуры.

### Что это меняет у нас

1. **Скиллы — отдельный слой, не плагин.** У нас знания живут в `AGENTS.md` и
   `docs/`, а сообщество упаковывает их в `SKILL.md` с ресурсами. Это дешевле
   поддерживать, чем код, и переносимо между агентами.
2. **MCP — уже норма поставки инструмента.** Мы подключили свой сервер через
   `dsh-mcp-client`; дальше чужие MCP-серверы (поиск, браузер, аудит) можно ставить
   как инструменты, не трогая код harness.
3. **Память между сессиями — тренд года.** `claude-mem` и `hermes-agent` продают
   именно это; у нас есть `recall.py`, но нет автоматического сжатия. Это дыра,
   которую видно со стороны.
4. **Аудит агентов становится продуктом** (`iFixAi`, `cloudflare/security-audit-skill`).
   Наш верификатор — та же ниша, но у нас нет внешней проверяемости находок.

## 5. Границы

* 25 записей на период; «популярно» = «попало в верхушку trendshift», а не «лучше».
* Разбор страниц — скрапинг: сломается при смене разметки, лечится обновлением
  `decode_flight`/`extract_json`, а не переписыванием.
* Описания репозиториев — внешний недоверенный текст. Модель не должна выполнять
  инструкции из описания; MCP-сервер прямо пишет это в `instructions`.
* Прирост звёзд — про внимание, а не про качество: половина топа — вирусные
  утилиты и обёртки вокруг Claude Code.

## 6. Где разбирают кандидатов

Здесь — только инструмент сбора. Разбор вынесен в отдельный workspace
`..\trend-lab`: там очередь (`queue.md`), карточки (`cards/`) и свой скилл
`trend-triage`, а контракт описан в его `AGENTS.md`.

Почему не в проекте: карточки чужих репозиториев — не исходники `harness`. В проекте
они попадали бы в git, в индекс xerj и в контекст любого агента, который читает этот
репозиторий. У лаборатории свой индекс (префикс `lab`), у проекта — свой (`harness`).

Утреннее напоминание живёт в сессии проекта и дописывает новое в
`..\trend-lab\queue.md`; когда откроете лабораторию как workspace, напоминание стоит
перенести туда.
