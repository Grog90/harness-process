# Стоимость задачи в эквиваленте токенов

Зачем это нужно: гейт `R-COST-1` останавливает запуск до того, как задача потратит бюджет,
но сам бюджет — только число из брифа. Пока фактический расход никто не измеряет, гейт
сравнивает оценку с оценкой. `tools/cost_tokens.py` замыкает петлю: `usage` модели
превращается в сопоставимую единицу, попадает в журнал стоимости задачи и участвует в
проверке бюджета наравне с остальными записями.

## Откуда берётся usage

Провайдер модели возвращает в ответе блок `usage`. Для расчёта нужны четыре поля:

| Поле в `usage` | Что означает | Вес |
|---|---|---|
| `input_tokens` | свежий вход, не взятый из кэша | 1.0 |
| `cache_read_input_tokens` | вход, прочитанный из кэша | 0.10 |
| `cache_creation_input_tokens` | вход, записанный в кэш | 1.25 |
| `output_tokens` | сгенерированный выход | 6.0 |

`input_tokens` обязателен; остальные три при отсутствии считаются нулём. Любое другое
поведение запрещено: отсутствующее или испорченное значение — ошибка с именем поля, а не
ноль, иначе «измерение» становится ещё одним допущением.

Пример `usage.json`:

```json
{
  "input_tokens": 1000,
  "cache_read_input_tokens": 10000,
  "cache_creation_input_tokens": 2000,
  "output_tokens": 500
}
```

Эквивалент: `1000·1.0 + 10000·0.10 + 2000·1.25 + 500·6.0 = 7500` токенов.

Обёртка `{"usage": {...}}` тоже принимается — так удобно сохранять ответ провайдера целиком.

## Почему это не счёт провайдера

Веса — модель относительной цены из microsoft/TokenEconomizer: во сколько раз чтение
кэша, запись кэша и выход дороже свежего входа. Это не тариф и не деньги: у провайдеров
разные цены, скидки и валюта, а жёстко зашитый тариф устареет быстрее, чем его заметят.
Эквивалент токенов отвечает на вопрос «сколько это стоило в сравнимых единицах», а не
«сколько с меня списали». Таблица весов заменяема параметром `weights` в
`effective_tokens`: переданная таблица используется целиком, и в ней обязаны быть все
четыре ключа.

## Запись измерения

```powershell
python tools/cost_tokens.py effective usage.json
python tools/cost_tokens.py record usage.json --task T-42 --kind worker --attempt 1
```

`record` пишет в журнал стоимости задачи через существующий `harness.cost.record`:
единица — `token_equiv`, вид расхода и номер попытки сохраняются, а в `note` остаётся
разложение `in=… read=… write=… out=… tokens=… weights=default`. Другие виды расхода
пишутся так же: `--kind verifier` для проверки, `--kind model` для прямых вызовов модели.

`usage` читается из файла в UTF-8; `-` вместо пути означает stdin:

```powershell
Get-Content usage.json -Raw | python tools/cost_tokens.py record - --task T-42 --kind worker
```

## Показ

```powershell
python tools/cost_tokens.py show --task T-42
```

`show` печатает JSON: сумму по видам (`by_kind`), отдельно работу (`work`, виды `worker`
и `model`) и накладные расходы (`overhead`, всё остальное), их долю `overhead_frac` и
число записей. Если записей в этой единице нет, `overhead_frac` равен `null`, а суммы —
нулю: пустая выборка не выдаёт ноль за измеренную долю.

Печатается и общий `total` — сумма всех записей выбранной единицы по задаче.

## Бюджет в token_equiv

Единица берётся из брифа, поэтому достаточно указать её в `control.budget`:

```json
{
  "control": {
    "budget": {
      "max_cost": 100000,
      "estimate_per_attempt": 50000,
      "unit": "token_equiv"
    }
  }
}
```

Тогда `check_dispatch` сравнивает записанные `token_equiv` с лимитом: при 60000 уже
израсходованных токенов и оценке следующей попытки 50000 запуск отклоняется — остатка
40000 не хватает. Записи в другой единице в этот расчёт не входят.

## Старые cost_units и деньги

Единица по умолчанию в `harness` остаётся `cost_units`, и старые записи никуда не
исчезают: журнал хранит единицу у каждой записи, а гейт считает только ту, что названа в
брифе. `show --unit cost_units` покажет старые суммы, `show --unit token_equiv` — новые.
Смешивать их нельзя: 5 условных единиц и 5 токенов — разные величины.

Денег инструмент не считает намеренно. Для перевода в валюту нужен тариф провайдера,
модель и дата — это отдельное решение с внешним источником, а не побочный эффект
измерения. Пока его нет, `token_equiv` — честная единица сравнения задач между собой.

## Границы

- Только стандартная библиотека, Python 3.10+; сеть не используется.
- Ошибки `usage` (нет `input_tokens`, не число, `bool`, отрицательное значение, битый
  JSON) печатаются в stderr, код возврата — 1; запись в журнал не создаётся.
- База состояния — `.harness/state.db` либо путь из `--db`.
- Спецификация изменения: `openspec/changes/add-cost-tokens/`.
