# Spec Delta

## Purpose

Даёт циклу измерение стоимости: `usage` модели превращается в сопоставимую единицу, попадает в журнал стоимости задачи и участвует в гейте `R-COST-1` — без правки ядра и без перевода в деньги.

## ADDED Requirements

### Requirement: usage переводится в эквивалент токенов

Инструмент ДОЛЖЕН (SHALL) считать расход как сумму четырёх слагаемых: свежий вход с весом 1.0, чтение кэша с весом 0.10, запись кэша с весом 1.25, выход с весом 6.0; отсутствующие необязательные поля считаются нулём.

#### Scenario: Веса кэша применяются

- **WHEN** usage содержит 1000 входных, 10000 прочитанных из кэша, 2000 записанных в кэш и 500 выходных токенов
- **THEN** эквивалент равен 7500 токенам

#### Scenario: Таблица весов заменяема

- **WHEN** вызывающий передал собственную таблицу весов
- **THEN** расчёт идёт по ней целиком, а не по значениям по умолчанию

### Requirement: Неполный usage — ошибка, а не ноль

Инструмент НЕ ДОЛЖЕН (MUST NOT) молча подставлять ноль вместо отсутствующего или испорченного значения: отсутствие входных токенов, нечисловое значение и отрицательное значение ДОЛЖНЫ (MUST) давать ошибку с именем поля.

#### Scenario: Отсутствие входных токенов отклоняется

- **WHEN** в usage нет поля с входными токенами
- **THEN** возвращается ошибка с именем этого поля, и запись в журнал не создаётся

#### Scenario: Отрицательное значение отклоняется

- **WHEN** в usage отрицательный выход
- **THEN** возвращается ошибка с именем поля, и запись в журнал не создаётся

### Requirement: Измерение попадает в журнал стоимости задачи

Инструмент ДОЛЖЕН (SHALL) записывать посчитанный эквивалент в журнал стоимости задачи в единице `token_equiv` через существующий учёт, сохраняя вид расхода и номер попытки.

#### Scenario: Запись попадает в единицу token_equiv

- **WHEN** usage записан для задачи с видом расхода и номером попытки
- **THEN** в журнале появилась запись с посчитанной суммой, единицей `token_equiv`, тем же видом и той же попыткой

### Requirement: Токенный бюджет участвует в гейте до запуска

Гейт `R-COST-1` ДОЛЖЕН (SHALL) отклонять запуск по бюджету, заданному в `token_equiv`, на основании записанных измерений, а записи в другой единице НЕ ДОЛЖНЫ (MUST NOT) на него влиять.

#### Scenario: Бюджет в токенах останавливает запуск

- **WHEN** по задаче записано 60000 токенов и в брифе задан предел 100000 при оценке попытки 50000
- **THEN** диспетч отклоняется с указанием остатка и оценки

#### Scenario: Чужая единица не складывается с токенами

- **WHEN** по задаче записаны 5 условных единиц и запуск проверяется против бюджета в `token_equiv`
- **THEN** эти 5 единиц не считаются израсходованными токенами

### Requirement: Работа и накладные расходы разделены

Инструмент ДОЛЖЕН (SHALL) показывать сумму по видам расхода, отдельно работу и накладные расходы, и их долю; при отсутствии записей доля ДОЛЖНА (MUST) быть пустой, а не нулевой.

#### Scenario: Накладные расходы считаются отдельно

- **WHEN** по задаче записаны 7000 токенов работы и 3000 токенов проверки
- **THEN** показ даёт работу 7000, накладные 3000 и долю 0.3

#### Scenario: Пустая выборка не выдаёт ноль за факт

- **WHEN** по задаче нет ни одной записи в этой единице
- **THEN** доля накладных расходов пуста, а суммарные значения равны нулю
