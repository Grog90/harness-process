# Design: доска как продукт

## Decisions

**1. Данные не трогаем.**
Источник остаётся `/harness-panel/metrics.json` и SQLite; меняется только
представление.

**2. Плагин — основной вид, HTML — fallback.**
Плагин даёт тему DSH, навигацию и полноэкранную доску. HTML остаётся для CI,
шаринга и работы без DSH. Оба используют один JSON.

**3. `main` + кнопка, без нового sidebar-пункта.**
Слот `main` — keyed; регистрируем `harness-board`, открываем через
`ctx.layout.selectPanel`. Если слот/сервис недоступен, компактная панель не
ломается (try/catch вокруг регистраций).

**4. Фильтры на клиенте.**
Активные по умолчанию; поиск по `change_id`; `CANCELLED` не в	default-виде.
HTML делает то же ванильным JS, без зависимостей.

## Risks

- Client-бандл DSH не HMR-ится надёжно: после установки нужен перезапуск.
- `main` keyed-слот может отсутствовать в старых DSH — тогда только компактная
  панель.
- HTML и плагин могут разойтись; общий контракт — JSON-поля, тесты на оба вида.
- Фильтры на клиенте не меняют серверные метрики; это только вид.
