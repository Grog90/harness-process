# Spec Delta

## Purpose

Даёт `harness` уровень изменения: согласованный план, review-записи, трассировку и
привязку задач к версии плана. Без этого бриф остаётся самодостаточным пакетом
задачи, но не доказательством, что задача входит в согласованное изменение.

## ADDED Requirements

### Requirement: [REQ-CHG-1] Изменение проходит состояния и запрещённые переходы

Система ДОЛЖНА (SHALL) вести состояние изменения и разрешать только переходы из
таблицы; переход, которого нет в таблице, ДОЛЖЕН (MUST) отклоняться с именем
правила и текущим состоянием.

#### Scenario: [CASE-CHG-1-1] Запрещённый переход отклоняется

- **WHEN** change находится в DRAFT и запрошен переход `ready`
- **THEN** переход отклоняется с правилом R-CHG-1 и указанием, что Ready возможен из DESIGN_AGREED

#### Scenario: [CASE-CHG-1-2] Правка плана сбрасывает Ready

- **WHEN** change в READY и запрошена ревизия
- **THEN** редакция увеличивается, состояние становится SPECS_AGREED, spec_ref сбрасывается

### Requirement: [REQ-CHG-2] Ready требует review-записей всех ролей

Система ДОЛЖНА (SHALL) требовать для перехода в READY актуальные approve-записи
по proposal, specs, design и tasks; запись валидна только при совпадении хеша
артефакта, наличии критериев и отличии проверяющего от автора.

#### Scenario: [CASE-CHG-2-1] Ready без review заблокирован

- **WHEN** артефакты change заполнены, но review-записей нет
- **THEN** Ready отклоняется с перечнем артефактов и ролей, которых не хватает

#### Scenario: [CASE-CHG-2-2] Самопроверка запрещена

- **WHEN** author_id и reviewer_id совпадают
- **THEN** review отклоняется с правилом R-REV-2

#### Scenario: [CASE-CHG-2-3] Правка артефакта инвалидирует review

- **WHEN** после review артефакт изменён
- **THEN** его прежний хеш не совпадает, и Ready снова заблокирован

### Requirement: [REQ-CHG-3] Трассировка REQ → CASE → task проверяется

Система ДОЛЖНА (SHALL) выдавать требованиям и сценариям устойчивые ID, проверять,
что каждое требование имеет сценарий, а каждая задача — файл и способ проверки;
разрыв ДОЛЖЕН (MUST) блокировать Ready.

#### Scenario: [CASE-CHG-3-1] Требование без сценария

- **WHEN** в дельте specs есть Requirement без Scenario
- **THEN** trace не проходит, Ready заблокирован, проблема называет ID требования

#### Scenario: [CASE-CHG-3-2] Задача без пути и проверки

- **WHEN** задача в tasks.md не содержит файла или команды проверки
- **THEN** trace сообщает об этом и Ready не проходит

### Requirement: [REQ-CHG-4] spec_ref пиннит редакцию плана

Бриф по change ДОЛЖЕН (SHALL) нести полный Git SHA плана; `specgate` ДОЛЖЕН
принимать только живой change с совпадающим digest спеки.

#### Scenario: [CASE-CHG-4-1] Короткий или чужой SHA отклоняется

- **WHEN** бриф несёт spec_ref короче 40 hex или не совпадающий с планом
- **THEN** диспетч отклоняется с правилом R-REF-1

#### Scenario: [CASE-CHG-4-2] Архивный change не является связью

- **WHEN** код коммитится со ссылкой на change, лежащий в archive
- **THEN** specgate отклоняет коммит с указанием, что change завершён

#### Scenario: [CASE-CHG-4-3] Изменённая спека блокирует коммит

- **WHEN** после сборки брифа spec.md изменён
- **THEN** digest не совпадает, и specgate отклоняет коммит

### Requirement: [REQ-CHG-5] Задача по change запускается только после Ready

Система ДОЛЖНА (SHALL) отклонять диспетч задачи, привязанной к зарегистрированному
change, если change не в READY/IN_PROGRESS; первый диспетч переводит change в
IN_PROGRESS.

#### Scenario: [CASE-CHG-5-1] Диспетч до Ready

- **WHEN** change зарегистрирован, но находится в DRAFT
- **THEN** диспетч отклоняется с R-CHG-1, задача остаётся без запуска

#### Scenario: [CASE-CHG-5-2] Диспетч после Ready начинает работу

- **WHEN** change в READY, бриф несёт совпадающий spec_ref
- **THEN** диспетч разрешён, change переходит в IN_PROGRESS

### Requirement: [REQ-CHG-6] Бриф из change сохраняет связи

`brief from-change` ДОЛЖЕН (SHALL) заполнять `change_id`, `spec_ref` и для каждого
критерия — `req_id` и `case_id`, чтобы вердикт и коммит можно было связать с
требованием.

#### Scenario: [CASE-CHG-6-1] Критерии несут REQ и CASE

- **WHEN** бриф собран из change со сценариями
- **THEN** каждый критерий содержит req_id и case_id, а бриф валиден
