# Design: панель harness

## Decisions

**1. Слот `conversation.composer.dock`.**
Он уже выделяет место под композером и не перекрывает чат; регистрация с своим
id `harness-panel`, order 20. Встроенные `activity`/`usage` не заменяются.

**2. Источник данных — `/metrics.json` доски.**
Панель делает `fetch` раз в 15 с; URL по умолчанию `http://127.0.0.1:8765`,
переопределяется `localStorage.harnessBoardUrl`. Сервер доски отдаёт
`Access-Control-Allow-Origin: *`, иначе браузер режет запрос.

**3. Offline честный.**
Ошибка fetch показывается как `доска offline` и команда запуска; панель не
имитирует пустые нули. Мутаций нет: только чтение и локальный refresh.

## Risks

- Нужен запущенный `harness board --serve`; без него панель offline.
- Polling 15 с, а не SSE; данные могут отставать.
- CORS `*` у локального сервера: он слушает localhost, но любой процесс на машине
  может прочитать metrics.
- Визуальная проверка в GUI требует авторизации; Inspect подтверждает только
  регистрацию, не пиксели.
