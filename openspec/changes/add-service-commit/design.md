# Design: коммит и tree-snapshot сервисов

## Decisions

**1. Один снимок на задачу, а не два.**

`snapshot_for_task(root, task)` берёт `services` из `brief_json`, оставляет только
`write=true` и считает `compute_tree`: hash от `(главное дерево, [(name, path,
snapshot)])`. Read-only сервисы не входят: они не кандидат.

**2. Finalize коммитит каждый сервис отдельно.**

`commit_services` для каждого writable-сервиса:

- если сервис — самостоятельный git-репозиторий: проверяет `is_git_repo`, берёт
  `write_set`, сверяет с `allowed_files` после `service:<name>/`, делает
  `git add`/`commit` только разрешённых путей, проверяет leftover и возвращает
  `{name, path, commit_sha, paths}`;
- если сервис лежит внутри главного корня и своего git нет: помечает его
  `mode=main`, файлы проверяются и коммитятся главным репозиторием, SHA в
  `service_commits` — SHA главного коммита;
- отсутствующий каталог/битый git — `R-FINAL-1`.

Сервисные коммиты создаются до главного; главный — последним, чтобы
`tasks.commit_sha` указывал на него. Каждый SHA пишется в `commits` с тем же
`task_id` и `snapshot_id`.

**3. Evidence получает коммиты, а не только файлы.**

`write_evidence` добавляет `task_commits: {task_id: [commits]}`. Это покрывает
сервисные SHA, которые иначе жили бы только в SQLite.

**4. Граница v1.**

Push, PR, merge order и разрешение конфликтов не делаются. Сервисный репозиторий
должен существовать; если это отдельный git — коммит отдельный, если in-root без
своего git — главный. Отсутствующий каталог даёт R-FINAL-1 в финализаторе, а не
молчаливый пропуск. Частичный коммит (сервис A закоммичен, B упал) называется в
ошибке и не откатывается автоматически.

## Risks

- Частичный коммит: сервисы закоммичены, главный упал. Повторный finalize увидит
  сервис уже чистым; это надо назвать в выводе ошибки, но откат не автоматизируется.
- Сервисный репозиторий может иметь свои хуки; commit вызывается с `-c user.*`, но
  хуки не отключаются.
- Snapshot читает чужие деревья целиком: для больших сервисов это дороже; кэша нет.
