# Design: подписанные коммиты

## Decisions

**1. SSH-подпись, не GPG.**
`git` 2.50 умеет `gpg.format=ssh`; отдельный GPG не нужен. Ключ ed25519 без
пароля — иначе автономные коммиты невозможны; риск кражи ключа принят.

**2. Приватный ключ вне репозитория.**
`~/.ssh/harness_signing`; в репозитории только `.github/allowed_signers` с
публичным ключом. Это позволяет `git verify-commit` локально и в CI.

**3. CI проверяет диапазон, доверие — из base.**
Для push проверяются коммиты `before..HEAD`, для PR — `base..head`; GitHub
merge-коммит не подписывается и в диапазон не входит. Для PR allowed_signers
берётся из base-ветки, иначе автор PR мог бы добавить свой ключ. Checkout —
`fetch-depth: 0`.

**4. Финализатор коммитит как `harness@harness.local`.**
Поэтому в allowed_signers два principal с одним ключом: владелец и финализатор.
Иначе подписанный финализатором коммит не прошёл бы verify по principal.

## Risks

- Ключ без пароля: компрометация машины = компрометация подписи.
- GitHub-верификация не включена автоматически; CI-проверка — источник правды.
- Ротация ручная: новый ключ → обновить allowed_signers → переподписать новые
  коммиты; старые остаются с прежним ключом.
- Branch protection не настраивается (free private), обязательность — runbook/CI.
- **Вне rules.json:** подпись — git/CI-гейт, а не hook harness; отдельного
  R-SIGN-1 нет, потому что control point живёт в workflow, а не в Python-хуке.
- Старые коммиты (до `c84537a`) не подписаны и не проверяются; merge через
  GitHub UI создаёт неподписанный merge-коммит, поэтому вливать нужно локальным
  подписанным merge.
