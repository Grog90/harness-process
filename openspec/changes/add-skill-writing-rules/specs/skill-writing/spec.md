# Spec Delta

## Purpose

Скилл — это текст, который модель читает либо всегда (описание в каталоге), либо за указателем (тело). Дельта задаёт контракт файла скилла и правила, по которым ревьюится любая агентская инструкция, чтобы правка скилла не решала заново одни и те же вопросы. Проверяется детерминированно, где это возможно; там, где невозможно, критерий остаётся текстом и назван текстом.

## ADDED Requirements

### Requirement: Фронтматтер скилла однозначен и валиден

Каждый `SKILL.md` в `.dsh/skills/*` ДОЛЖЕН (SHALL) начинаться с блока `---` и содержать `name` и `description`; `name` ДОЛЖЕН совпадать с именем каталога; `description` ДОЛЖНО (MUST) быть одной строкой без `": "` и без `" #"` — иначе YAML ломается, и установщик молча пропускает скилл.

Исключение: `.dsh/skills/desktop/SKILL.md` не имеет фронтматтера, а его описание в каталоге приходит из `tools/desktop_mcp.py` (`INSTRUCTIONS`); файл остаётся вне проверки, причина записана в `docs/SKILLS.md` и в тесте.

#### Scenario: Файл без фронтматтера отвергается

- **WHEN** у скилла (кроме `desktop`) нет блока `---` с `name` и `description`
- **THEN** проверка падает с именем файла, а не молча пропускает его

#### Scenario: Описание с двоеточием и пробелом отвергается

- **WHEN** `description` содержит `": "` вне кавычек
- **THEN** проверка падает: это невалидный YAML, из-за которого установщик пропускает скилл

#### Scenario: Имя совпадает с каталогом

- **WHEN** `name` не равен имени каталога скилла
- **THEN** проверка падает с обоими именами

#### Scenario: Синтетический дефект ловится

- **WHEN** проверке подан фронтматтер с `": "` в описании
- **THEN** она возвращает ошибку, а не пустой список: проверка доказывает, что ловит, а не просто проходит

### Requirement: Описание — только триггеры

`description` ДОЛЖНО (MUST) говорить, что это и когда звать, и НЕ ДОЛЖНО (MUST NOT) содержать процедуру: обратные кавычки с именами инструментов и команд запрещены, длина — не больше 400 символов. Описание попадает в системный промпт как оглавление, и инструкция в нём выполняется до загрузки тела.

#### Scenario: Инструкция в описании отвергается

- **WHEN** в `description` есть обратные кавычки (имя инструмента или команды)
- **THEN** проверка падает: описание — указатель, а не процедура

#### Scenario: Слишком длинное описание отвергается

- **WHEN** `description` длиннее 400 символов
- **THEN** проверка падает с длиной и именем скилла

### Requirement: У наших скиллов есть проверяемый конец

Скиллы `web-check`, `youtube-check` и `vpn-router` ДОЛЖНЫ (SHALL) заканчиваться разделом `## Готово, когда` с проверяемыми пунктами; чужой пакет `openspec-*` и `desktop` не переписываются.

#### Scenario: «Готово, когда» есть у трёх наших скиллов

- **WHEN** проверка смотрит на `web-check`, `youtube-check`, `vpn-router`
- **THEN** в каждом найден заголовок `## Готово, когда` и хотя бы один пункт списка под ним

### Requirement: Тяжёлый материал — за указателем

`vpn-router/SKILL.md` НЕ ДОЛЖЕН (MUST NOT) содержать датированные замеры Instagram: они ДОЛЖНЫ (MUST) лежать в `vpn-router/reference.md`, на который ссылается SKILL.md.

#### Scenario: Датированные секции ушли в reference

- **WHEN** проверка ищет `29.10.2026` в `vpn-router/SKILL.md`
- **THEN** совпадений нет, а в `reference.md` они есть

### Requirement: Критерий ступени 3 записан

`docs/LESSONS.md` ДОЛЖЕН (SHALL) содержать критерий: нарушение, которое ловится детерминированно, лечится проверкой, а не текстом правила.

#### Scenario: Критерий есть в документе

- **WHEN** проверка ищет в `docs/LESSONS.md` формулировку «ловится детерминированно»
- **THEN** формулировка найдена
