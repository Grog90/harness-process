# Spec Delta

## Purpose

Чужой текст приходит агенту как данные, но выглядит как задача. Машинные проверки видят
действия, а не смысл. Дельта задаёт список признаков и порядок действий, чтобы решение
«это подсказка или задача» не принималось заново в каждом чате.

## ADDED Requirements

### Requirement: Признаки подозрительного текста названы

`docs/PROMPT-DEFENSE.md` ДОЛЖЕН (SHALL) перечислять не меньше шести признаков: похожие
символы, давление срочностью, команды внутри чужого документа, просьба показать секреты,
требование отключить проверку, скрытый текст, смена роли, просьба скрыть следы.

#### Scenario: Документ короче шести признаков отвергается

- **WHEN** в документе меньше шести пунктов списка признаков
- **THEN** проверка падает с числом найденных пунктов

### Requirement: Действия при подозрении описаны

Документ ДОЛЖЕН (SHALL) содержать раздел «Что делать» с порядком: назвать просящего,
остановиться при просьбе о секретах или отключении проверки, спросить человека при
противоречии правилам проекта.

#### Scenario: Раздел «Что делать» отсутствует

- **WHEN** в документе нет раздела «Что делать»
- **THEN** проверка падает

### Requirement: Памятка не выдаёт себя за проверку

Документ ДОЛЖЕН (MUST) содержать раздел «Границы» и прямо говорить, что он не заменяет
автоматические проверки.

#### Scenario: Граница названа

- **WHEN** в документе нет раздела «Границы» или слова о том, что он не заменяет проверки
- **THEN** проверка падает

### Requirement: Указатель есть в контракте

`AGENTS.md` ДОЛЖЕН (SHALL) ссылаться на `docs/PROMPT-DEFENSE.md`, иначе документ не
найдётся в работе.

#### Scenario: Указатель потерян

- **WHEN** в `AGENTS.md` нет строки с путём `docs/PROMPT-DEFENSE.md`
- **THEN** проверка падает
