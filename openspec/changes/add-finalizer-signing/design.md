# Design: подпись финализатора

## Decisions

**1. Условие обязательности.**
Подпись требуется, если локально `commit.gpgsign=true` или
`HARNESS_REQUIRE_SIGNED=1`. Это сохраняет тесты на временных репозиториях без
ключей и делает реальный репозиторий (где флаг включён) подписывающим.

**2. Preflight до любых коммитов.**
`signing.context(root)` проверяет `gpg.format`, `user.signingkey` и
`allowedSignersFile`; ошибка — `R-FINAL-2` до `commit_services`, чтобы не
создавать частичные коммиты.

**3. Проверка после коммита.**
`signing.verify` вызывает `git verify-commit HEAD`; сервис проверяется до записи
в БД, main — до `record_commit`. Неудача откатывает уже сделанное.

**4. Сервисы и merge.**
Используется контекст основного репозитория: ключ и allowed_signers общие;
сервисный репозиторий не обязан иметь свою конфигурацию.

**5. Это tamper-evident, не tamper-proof.**
Подпись ловит неподписанный/чужой коммит, но финализатор всё ещё живёт в том же
дереве и может быть изменён. Полный tamper-proof — отдельный остаток.

## Risks

- Ключ без пароля: доступ к машине = доступ к подписи.
- `git verify-commit` в старых версиях git не умеет SSH; тогда подпись не
  включится (preflight не требует формат ssh).
- Сервисный репозиторий с другой политикой подписи может не принять ключ
  основного; это обнаружится на verify и откатится.
- Тесты без ключа не проверяют успешную подпись, только отказ preflight.
