# Предложение: адаптер DSH ↔ harness

## Problem

Guard уже проверяет инструменты DSH по `.harness/guard-scope.json`, но сама
агентская сессия не знает, что она — задача harness: роль, task_id, allowed_files,
сервисы и фазу приходится передавать словами. `harness` и DSH остаются двумя
контурами, связанными вручную.

## What Changes

- Новый host-плагин `@local/harness-session`:
  - добавляет в системный контекст сессии активную задачу harness (task_id, роль,
    allowed_files, сервисы, фазу, попытку) из `.harness/guard-scope.json`;
  - регистрирует read-only инструмент `harness_task` со статусом задачи
    (`python -m harness --json task status`), чтобы агент не угадывал состояние.
- Плагин не диспетчит, не выносит вердикт и не коммитит: это остаётся за
  управляющим процессом и соответствующими ролями.

## Impact

- Класс риска: **L1** (плагин видит состояние задачи, но не расширяет запись).
- Новые файлы `plugins/harness-session/`, тесты, документация; установка в профиль —
  отдельное действие.
- Автоматический dispatch/verdict/commit не входят.

## Out of Scope

- Автозапуск задачи при создании сессии.
- Автоматический вердикт и коммит из DSH.
- Изменение `harness-guard`.
