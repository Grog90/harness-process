# Design: автопривязка сессии

## Decisions

**1. Файл привязки, а не env.**
`.harness/session-attach.json` переживает перезапуск DSH и читается плагином в
момент `agent/created`; env остаётся только для явного override.

**2. Один диспетч на задачу.**
Плагин сверяет `scope.task_id`; если он уже равен привязанному, повторного вызова
нет. `--primary-agent` — id агента, создавшего сессию, чтобы guard дал ему роль
orchestrator, а дочерним — роль фазы.

**3. Ошибка не роняет сессию.**
spawnSync с таймаутом; результат и stderr пишутся в `.harness/session-attach.error`.
Контекст задачи появится только после успешного dispatch (scope публикует CLI).

**4. Граница.**
Автоматизируется только dispatch. Submit остаётся действием воркера/оркестратора,
verdict — проверяющего, accept — человека. Это сохраняет независимость гейтов.

## Risks

- `agent/created` в общем профиле может сработать для чужой сессии; привязка — один
  файл на корень, несколько одновременных задач не поддерживаются.
- spawnSync блокирует создание агента до 15 с.
- Если задача не в BRIEF_READY, dispatch откажет; это будет видно в error-файле.
