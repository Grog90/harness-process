# Design: публикация и откат

## Decisions

**1. Push — явная команда.**
`lane push` пушит только ветку `harness/<task>` с `--set-upstream`, без `--force`.
PR создаётся `gh pr create`; отсутствие `gh` — отказ, иначе оператор думает, что PR
есть. Требуется `may_commit`.

**2. Откат — reset --soft.**
Перед коммитом сервиса запоминается `previous_sha`. Любая ошибка после этого
(включая падение главного коммита) вызывает `_rollback_records`: `reset --soft`
возвращает HEAD, но оставляет изменения в индексе — работа не теряется. Записи
`commits` удаляются, `tasks.commit_sha` очищается.

**3. Порядок.**
Сервисы коммитятся первыми; главный — последним. При успехе все записи остаются;
при ошибке откат идёт в обратном порядке, включая главный.

## Risks

- `reset --soft` не трогает working tree, но меняет HEAD; при внешнем параллельном
  коммите в тот же репозиторий откат может затронуть не тот коммит — это
  контролируемый локальный финализатор.
- Push сервисных репозиториев не реализован.
- `gh` требует авторизации; ошибка gh возвращается как отказ.
