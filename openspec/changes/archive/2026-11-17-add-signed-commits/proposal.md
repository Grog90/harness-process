# Предложение: L2 — подписанные коммиты

## Problem

Коммиты не подписаны: нельзя проверить, что их создал процесс, владеющий
ключом, а не подменённый агент/процесс. Подпись подтверждает доступ к ключу,
а не личность человека.

## What Changes

- локальный SSH-ключ подписи (вне репозитория, `~/.ssh/harness_signing`);
- `git config commit.gpgsign=true`, `gpg.format=ssh`, `user.signingkey`;
- `.github/allowed_signers` с публичным ключом в репозитории;
- CI-шаг `git verify-commit HEAD` с этим allowed_signers;
- `docs/SIGNING.md`: как проверить, где ключ, что не загружено в GitHub.

## Impact

- Класс риска: **L2** (изменение git-конфигурации и доверия к коммитам).
- Приватный ключ не коммитится; публичный — да, он и есть доверие.
- GitHub-верификация появится только после загрузки ключа в аккаунт; локально/CI
  проверка работает без этого.

## Out of Scope

- Загрузка ключа в GitHub и обязательная branch protection.
- Подпись тегов/релизов и аппаратный токен.
- Ротация ключа (описана как ручная процедура).
