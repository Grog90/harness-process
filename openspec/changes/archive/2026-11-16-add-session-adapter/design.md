# Design: адаптер DSH ↔ harness

## Decisions

**1. Контекст, а не автодиспетч.**
Плагин читает `.harness/guard-scope.json` — тот же файл, по которому guard уже
считает роль. Это единственный источник истины; второго списка прав нет.
Контекст собирается на каждый шаг (`systemPrompt.context` с функцией), поэтому
смена задачи видна без перезапуска сессии. Без scope провайдер возвращает пустой
текст; без найденного корня провайдер не регистрируется.

**2. Инструмент только читает.**
`harness_task` вызывает `python -m harness --root <root> --json task status --task <id>`
и возвращает `{ok,status}`. Dispatch/verdict/commit не регистрируются: у агента нет
чужих гейтов. task_id берётся из scope или параметра; произвольный чужой task_id
read-only, это не расширение прав. spawnSync блокирует host event loop до 30 с —
осознанная цена простоты, вынесено в Risks.

**3. Python ищется явно.**
`config.python` → `HARNESS_PYTHON` → `python` в PATH. Корень — `config.root` →
`HARNESS_ROOT` → указатель `~/.dsh/harness-root` → текущий каталог вверх до
`policies/policy.json`.

**4. Ошибки не ломают сессию.**
Нет scope/политики — контекст пропускается; ошибка CLI возвращается как
структурированная ошибка инструмента, а не исключение плагина.

## Risks

- Scope-файл может устареть между шагами; контекст отражает последний снимок.
- `python` может отсутствовать в PATH; тогда инструмент вернёт ошибку, а guard
  продолжит работать отдельно.
- Плагин установлен в профиле `desktop` 16.11.2026; в поставку harness не входит.
