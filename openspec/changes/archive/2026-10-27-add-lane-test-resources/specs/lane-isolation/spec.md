# Spec Delta

## Purpose

Даёт параллельным лейнам собственные ресурсы исполнения — порты, тестовую БД и
временный каталог — так, чтобы одновременный прогон проверок не мешал соседу, а
команды проверок получали эти ресурсы явно.

## ADDED Requirements

### Requirement: Слот ресурсов выделяется при создании лейна

`harness lane create` ДОЛЖЕН (SHALL) выделить задаче свободный слот и сохранить набор ресурсов
(индекс слота, база портов, путь тестовой БД, временный каталог) в состоянии задачи
вместе с именем лейна.

#### Scenario: Первый и второй лейн получают разные слоты
- **WHEN** создаются два лейна подряд без освобождения
- **THEN** первому выдан слот 0, второму — слот 1, и базы портов различаются

#### Scenario: Набор ресурсов возвращается создателю
- **WHEN** `harness lane create` завершился успешно
- **THEN** вывод содержит слот, базу портов, путь тестовой БД и временный каталог

### Requirement: Слот уникален среди живых лейнов

Система НЕ ДОЛЖНА (MUST NOT) выдавать слот, занятый живым лейном: повторная выдача — отказ с
правилом `R-WAVE-1`, а не совпадающие ресурсы у двух задач.

#### Scenario: Занятый слот не выдаётся дважды
- **WHEN** у живого лейна уже есть слот 0 и создаётся новый лейн
- **THEN** новый лейн получает другой слот, а не 0

### Requirement: Слот освобождается вместе с лейном

`harness lane remove` и `harness lane release` ДОЛЖНЫ (MUST) освобождать слот задачи, а слот
лейна, чей worktree исчез, ДОЛЖЕН считаться свободным при следующем выделении.

#### Scenario: Освобождённый слот переиспользуется
- **WHEN** лейн со слотом 0 удалён и создаётся новый лейн при отсутствии других живых
- **THEN** новый лейн получает слот 0

#### Scenario: Протухший лейн не блокирует ресурсы
- **WHEN** worktree лейна удалён в обход `harness` и создаётся новый лейн
- **THEN** слот исчезнувшего лейна считается свободным

### Requirement: Ресурсы лейна доступны до запуска проверок

`harness lane show` ДОЛЖЕН (MUST) возвращать для задачи тот же набор ресурсов, который был
выдан при создании, чтобы агент и человек видели одинаковые значения.

#### Scenario: Показ совпадает с выдачей
- **WHEN** после `lane create` вызывается `lane show` для той же задачи
- **THEN** слот, база портов, путь БД и временный каталог совпадают с выданными

### Requirement: Команды проверок получают ресурсы лейна

`harness checks run` для задачи в лейне ДОЛЖЕН (SHALL) передавать командам проверок переменные
`HARNESS_LANE_INDEX`, `HARNESS_LANE_PORT_BASE`, `HARNESS_TEST_DB` и `HARNESS_LANE_TMP`
со значениями из слота задачи.

#### Scenario: Проверка видит порт своего лейна
- **WHEN** в лейне со слотом 1 запускается команда проверки, печатающая окружение
- **THEN** её вывод содержит базу портов слота 1, отличную от слота 0

#### Scenario: Задача вне лейна не получает переменных лейна
- **WHEN** проверки запускаются для задачи без лейна
- **THEN** переменные `HARNESS_LANE_*` в окружении команды отсутствуют

### Requirement: Ресурсы лейна не расширяют остальное окружение

Передача ресурсов НЕ ДОЛЖНА (MUST NOT) ослаблять белый список окружения проверок: переменные
хоста, не входящие в список, по-прежнему не попадают в прогон.

#### Scenario: Посторонняя переменная хоста не протекает
- **WHEN** в окружении хоста задана переменная вне белого списка и запускаются проверки
- **THEN** команда проверки не видит эту переменную
