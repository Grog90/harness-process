# Proposal: мультисервисные изменения (v1)

## Why

Change сейчас живёт в одном репозитории: `spec_ref` — один SHA, verification — один
прогон, сервисы в release/acceptance появились только как версии. Реальное изменение
часто трогает контракт и несколько сервисов, и приёмка должна собрать версии всех.

## What Changes

- `change new --service name=PATH[@SHA]` объявляет сервисы change; `change services`
  показывает их.
- Бриф получает `services` (имя, относительный путь, принятая версия) и валидирует их.
- `verification run --cwd PATH --service name=SHA` пишет прогоны по сервисам
  (`service:baseline`/`service:candidate`), check_report требует оба режима для каждого
  объявленного сервиса.
- Release/acceptance уже принимают несколько `--service name=SHA`; evidence-манифест
  собирает записи с версиями.

## Impact

- Один change может опираться на несколько сервисов и получить приёмку с несколькими SHA.
- Verification-отчёт расширен без второго формата: сервис `repo` остаётся совместимым.
- **Запись** в чужие репозитории пока не открыта: guard и gateway остаются
  одно­корневыми. Это честная граница v1, а не скрытая мультирепозиторность.

## Out of Scope

- Мультикорневая запись и merge order (следующий шаг).
- Интеграционная среда/e2e между сервисами.
- Автоматическое открытие PR в нескольких репозиториях.
