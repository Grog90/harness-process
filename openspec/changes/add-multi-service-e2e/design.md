# Design: multi-service e2e

## Decisions

**1. Копии, а не рабочие деревья.**
Каждый сервис копируется в temp без `.git`, `.harness`, `node_modules`; прогон не
меняет исходники и не зависит от текущего worktree. SHA берётся из `@SHA` или
`git rev-parse`.

**2. Env-контракт.**
`HARNESS_E2E_<NAME>_DIR` и `_SHA` — единственный способ команды узнать сервисы;
имена нормализуются в верхний регистр. Команда запускается из корня harness.

**3. Отчёт в evidence.**
`evidence/e2e-<change>.json` содержит exit, timed_out, duration, services,
stdout/stderr tail. Это evidence прогона, а не изменение плана.

**4. Гейт роли.**
Запуск требует `may_commit`; worker не инициирует интеграцию.

## Risks

- Копия без зависимостей: e2e — smoke, реальные БД/Docker не поднимаются.
- Команда — произвольная shell-строка с правами процесса; запускает оператор.
- Отчёт не входит в verification и не блокирует Ready автоматически.
- Большие сервисы копируются целиком; инкрементальности нет.
