# Design

## Context

Все данные процесса уже есть: `changes`, `change_events`, `change_reviews`, `tasks`,
`attempts`, `verdicts`, `findings`, `costs`, файлы `verification.json` и evidence.
Не хватает слоя, который отвечает на вопросы «что в очереди», «где застряло»,
«сколько живёт изменение» и «здоров ли процесс в CI».

## Decisions

**1. Метрики — проекция, не хранилище.**
`metrics.collect` читает SQLite и файлы change; ничего не пишет. Цифры нельзя
«поправить» отдельно от процесса. Отчёт — markdown/json, доска — HTML.

**2. Доска — статический снимок.**
`harness board --out` рендерит самодостаточный HTML: без сети, без JS, с экранированием
всех данных. Это честно: живой дашборд в DSH GUI — отдельный продукт, а не побочный
эффект harness. Обновление — повторный запуск.

**3. CI-снимок отделён от change-гейтов.**
`harness ci` проверяет здоровье harness (selftest, покрытие, метрики, тесты) и пишет
evidence. Он не заменяет release/accept/archive: CI может быть зелёным, а change —
не принятым.

**4. Версии в отчёте, а не в голове.**
CI-отчёт хранит Git HEAD, версию Python, числа selftest/правил и метрики; при
расхождении с прошлым снимком видно, что изменилось.

**5. Честные границы.**
OTLP — HTTP JSON, без protobuf/gRPC; встраивание доски в DSH GUI не делается.
Headless проверяется smoke-скриптом: он отличает «профиль не запускается» от
«запускается, но нет ключа», а не выдаёт второе за первое.

**6. Живая доска — локальный HTTPServer.**
`board --serve` открывает своё SQLite-соединение на запрос (sqlite3 не любит чужой
поток), отдаёт `/`, `/metrics.json`, `/healthz`; HTML автообновляется. Это не замена
DSH GUI и не сервер приложения.

**7. OTLP без SDK.**
Payload строится по OTLP/HTTP JSON вручную: resource/scope/gauge, asInt строками,
asDouble числами. Так экспорт проверяем без второй зависимости; protobuf/gRPC —
сознательно вне границ.

**8. Headless smoke — отдельный инструмент.**
`tools/headless_smoke.py` запускает `dsh headless --json`, парсит NDJSON и пишет
session/final reason в evidence. Отсутствие ключа — FAIL с причиной, а не «не проверяли».

## Risks / Trade-offs

- **Снимок устаревает** — это ожидаемо; в шапке доски стоит время генерации.
- **Метрики на малой выборке** — lead time и rework могут быть `None`/0; отчёт
  показывает число выборок, а не притворяется статистикой.
- **HTML — не live-UI** — человек должен обновить файл; зато нет сервера и прав.
- **CI запускает unittest** — долго; `--run-tests` опционален, по умолчанию только
  быстрые проверки.
