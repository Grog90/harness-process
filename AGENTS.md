# AGENTS.md — рабочий контракт для агента

Это не документация проекта: она в `README.md` и `docs/`. Здесь только то, что агент обязан
делать и чего не делать. Каждое правило ниже либо исполняемо, либо имеет владельца.

## Что за проект

`harness` — управляемый агентный цикл: роли с ограниченными правами, бриф, независимая
проверка с вердиктом-объектом, бюджет попыток, автомат состояний и матрица
`RULE → HOOK → ENFORCEMENT`. Python 3.10+, **только стандартная библиотека**, зависимостей нет.

Как писать скиллы и агентские инструкции — `docs/SKILLS.md`.

## Команды

```powershell
python -m harness selftest                       # исполняемые проверки правил
python -m unittest discover -s tests -v          # 454 unittest-проверки свойств
python -m harness coverage                       # покрытие правил, пробелы
python -m harness rule verify                    # правила менялись без записи?
python tools/lessons.py check                    # дисциплина этого файла и журнала
python tools/recall.py index                     # поиск по прошлым сессиям
python tools/recall.py search "вопрос"           # что уже обсуждали и почему
python tools/trendshift.py watch --ai-only       # тренды GitHub: что нового в топе
```

Внешние инструменты — это MCP-серверы, а не команды: `browser` (moli: страницы,
скриншоты), `xerj` (поиск по коду и докам), `trendshift` (тренды). Нода xerj должна
быть запущена (задача `xerj-node`, `127.0.0.1:9200`) — без неё `xerj_*` отвечают
ошибкой. Hindsight свёрнут 27.10.2026: факты о проекте — в `docs/FACTS.md`, а не в
отдельной памяти. Подробности: `docs/BROWSER.md`, `docs/XERJ.md`, `docs/TRENDSHIFT.md`.

## Поиск: сначала xerj, потом файлы

Порядок поиска — не вкус, а способ не читать файлы целиком. Проверка формулировки —
`tests/test_agents_contract.py`: она видит текст, а не поведение, и это честно.

1. «Где это в коде/доках» — начинаю с xerj: `xerj_def` для символа, `xerj_search` или
   `xerj_hybrid_search` для фразы, с фильтром `ax_path`/`ax_format` на смешанном корпусе;
   `xerj_map` — когда неизвестно, какие индексы есть.
2. `grep`/`read`/`glob` — когда путь известен, нужен точный литерал или файл маленький.
3. Промах xerj (ноль совпадений или не тот пассаж) называю в ответе и перехожу в grep:
   молчаливый переход неотличим от «не искал».
4. Нет ноды `127.0.0.1:9200` — говорю об этом, а не выдаю пустоту за отсутствие кода.
   Подробности и границы: `docs/XERJ.md`.

## Жёсткие правила

1. **Никаких новых зависимостей.** Только стандартная библиотека Python. Нужна библиотека —
   это отдельное решение с обоснованием, а не побочный эффект задачи. Зафиксированное
   исключение: OpenSpec CLI (`npx @fission-ai/openspec`) — внешний инструмент планирования,
   как git или редактор. В репозитории от него остаётся только markdown в `openspec/`;
   сам пакет не вендорится, и `harness` без него работает.
2. **Python 3.10 — нижняя граница.** Не использовать синтаксис и API новее 3.10
   (`match` можно, `tomllib`, `Self`, `itertools.batched` — нет). Локальный 3.13 этого не ловит.
3. **`policies/rules.json` не правится молча.** Любое изменение правила — через
   `python -m harness rule change --id R-XXX-N --reason "..."`; иначе `rule verify` увидит
   расхождение отпечатка (R-HOOK-1). Новое правило без реализации помечается
   `"implemented": false` явно, а не исчезает из матрицы.
4. **Не трогать состояние процесса:** `.harness/`, `evidence/`, `pipeline-log/` — это выход
   прогонов, а не исходники. Они в `.gitignore`; коммитить их нельзя.
5. **Тесты — часть изменения, а не послесловие.** Правка поведения без теста не принимается;
   `python -m unittest discover -s tests -v` должен быть зелёным до коммита.
6. **`docs/RULES_MATRIX.md` генерируется.** Руками не править: источник — `rules.json` и код
   хуков. Менять надо источник, потом перегенерировать.
7. **Кодировка:** UTF-8 без BOM, переводы строк `\n`. Текст документации — по-русски,
   идентификаторы в коде — по-английски.
8. **Windows/PowerShell:** пути с кириллицей и пробелами — только `-LiteralPath` и в кавычках;
   рабочую папку задавать параметром, а не `cd`; `&&` не использовать.
9. **Не переписывать чужой замысел.** Если архитектурное решение кажется неверным — сказать
   и предложить, а не «улучшить» по ходу задачи (исключение — прямая просьба).
10. **Изменение поведения начинается со спеки.** Код коммитится только с брифом, который
    ссылается на `openspec`-change (`spec_version: openspec:<имя>@<отпечаток>`); иначе
    `finalize` отказывает по `R-SPEC-1`. Бриф собирается командой
    `python -m harness brief from-change --change <имя>`. Обход — только
    `--allow-no-spec "причина"`, и причина попадает в журнал задачи.

## Процесс обучения на ошибках

Полное описание — [`docs/LESSONS.md`](docs/LESSONS.md). Коротко, три ступени:

| Ступень | Когда | Куда | Кто проверяет |
|---|---|---|---|
| 1. Случай | ошибка/тупик случился | `journal/YYYY-MM.md` | никто, это лог |
| 2. Правило | повторилось **дважды** | строка в разделе «Уроки» ниже | `tools/lessons.py check` |
| 3. Автоматика | правило нарушено ещё раз | `policies/rules.json` + тест в `selftest` | `harness coverage` |

Правило для агента в работе:

- **Потратил больше двух попыток на одну проблему — остановись и запиши** случай в журнал
  (`python tools/lessons.py new ...`), не откладывая до конца сессии: компакция контекста
  стирает середину разговора.
- В раздел «Уроки» ниже — только через `python tools/lessons.py promote <id> --apply`,
  и только если случай повторялся. Раздел всегда в контексте, поэтому он маленький.
- Если правило уже есть, а ошибка повторилась — это сигнал на ступень 3: нужен тест или хук,
  а не ещё один абзац текста.
- Привычка — запись с условием, весом и доказательством: поля и формула уверенности —
  [`docs/INSTINCTS.md`](docs/INSTINCTS.md), проверка — `python tools/instincts.py check`.

## Чего здесь нет

Этот файл не заменяет проверки. Он не мешает обойти шлюз, не ловит смысловой дефект, который
не заметил верификатор, и не действует на агентов, которые его не читают. Он снижает
вероятность повторной ошибки, а не исключает её — измеряется долей повторов, а не размером файла.
