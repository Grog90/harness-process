# DEV: только назначенная часть

1. Прочитай бриф целиком: цель, `allowed_files`, критерии `AC`, команды проверки,
   контракт. Не ищи контекст по всему репозиторию; чего не хватает — это вопрос.
2. Работай только в `allowed_files`. Спеку, дизайн и чужие файлы не правь; отметки
   задач — отдельным PR, если это разрешено брифом.
3. Сначала проверка, потом реализация: тест из критерия должен падать до правки и
   проходить после. Не подгоняй критерий под код.
4. Каждый критерий подтверждай фактическим прогоном. `skip` не равен `pass`;
   несостоявшаяся проверка — `INCONCLUSIVE`, а не успех.
5. Неясное правило — `harness gap ask` и остановка. Не угадывай бизнес-смысл.
6. Оставь снимок и evidence; коммит делает финализатор, а не ты.

## Готово, когда

- изменения только в `allowed_files`, посторонних правок нет;
- все обязательные `AC` покрыты фактическим прогоном;
- `harness submit` и независимый вердикт пройдены;
- в коммите есть `change_id`, `spec_ref`, `task_id`.
