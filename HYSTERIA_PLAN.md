# Hysteria 2 на Keenetic через AWG Manager — план

Составлен 2026-10-29 по документации и замерам, а не по догадкам.

## 1. Что нашли в источниках

### Официальная документация Hysteria 2

- **TPROXY** (`v2.hysteria.network/docs/advanced/TPROXY/`): прозрачный прокси работает
  только на Linux, требует и TCP, и UDP, и **обязательно** policy-routing:
  `ip rule add fwmark 0x1 lookup 100` + `ip route add local default dev lo table 100`.
  Правила живут в `mangle`, цепочка цепляется в `PREROUTING`.
- Защита от петель: клиент запускается отдельным пользователем, его собственный трафик
  исключается по `-m owner --uid-owner hysteria`.
- **Server** (`.../getting-started/Server/`): порт 443/udp, TLS (ACME или свой
  сертификат), `auth.type=password`, `masquerade` — обязателен для маскировки под
  HTTP/3. Без masquerade сервер отдаёт 404 на любой HTTP-запрос, что демаскирует.
- Клиент поддерживает два режима входа: `tcpRedirect`/`tcpTProxy` + `udpTProxy`
  (порты) — то есть перехват делает роутер, а не Hysteria.

### H-wave — готовый пакет для Keenetic (`github.com/for6to9si/H-wave`)

- Требует **Entware на USB**, компонент прошивки «Модули ядра подсистемы Netfilter»
  (`xt_TPROXY`, `xt_socket`, `xt_multiport`) и доступа по SSH.
- Внутри: `S96hysteria` (init), `hwave-conf.json` (порты, таблица, mark), и перехват
  **по connmark политики доступа Keenetic** — то есть по устройствам, а не по доменам.
- Доменами H-wave не управляет вообще: он заворачивает порты 80/443/8080 у устройств
  из выбранной политики.

### AWG Manager 2.19.22 — устройство API

- `POST /api/singbox/tunnels` принимает **share-ссылки** (`hy2://…`) построчно и
  создаёт управляемый туннель. Только после этого туннель появляется в модели AWGM
  и на него можно ссылаться в правилах.
- `POST /api/singbox/ndms-proxy {"enabled":true}` — «NDMS Proxy creation for
  sing-box tunnels»: создаёт в Keenetic интерфейс `ProxyN` для туннелей sing-box.
- Режимы роутера: `off ↔ tproxy ↔ fakeip-tun ↔ policy-tun`
  (`POST /api/singbox/router/mode`).
- `tproxy` работает **по политикам**: `deviceMode=policy`, устройства привязываются
  через `policy-devices/bind`, перехват — по connmark политики.

## 2. Почему предыдущие попытки провалились

| Что делали | Почему не сработало |
|---|---|
| Добавили hysteria2 в слот `config/user` | AWGM не считает его своим outbound: `orphan-rule`, правила игнорируются |
| Включили `tproxy` без привязки | правил перехвата не создаётся вообще |
| Привязали устройство к политике | у политики `Hwave` нет маршрута по умолчанию → у устройства умирает DNS и весь интернет |
| Ждали доменной маршрутизации | у Hysteria нет интерфейса, Keenetic некуда маршрутизировать домены |

## 3. Целевая схема

Правильный путь в AWGM — не слот конфига, а **управляемый туннель**:

```
Keenetic (домены из списков)
        │  DNS-маршрут на интерфейс ProxyN
        ▼
   ProxyN  ← создаёт AWGM по кнопке «NDMS Proxy»
        │
   sing-box (tunnel hy2-de, создан из share-ссылки)
        │
   Hysteria 2  →  177.177.230.47:443/udp
```

Тогда:
- устройства **не привязываются**;
- домены идут через привычные списки AWGM;
- Hysteria остаётся транспортом.

Если `ProxyN` не появится (ограничение версии), запасной путь — режим `fakeip-tun`:
он поднимает tun-интерфейс, и маршрутизация доменов работает через него.

## 4. Шаги

**Шаг 0. Подготовка (уже сделано).**
Сервер Hysteria 2 работает, бинарники на USB, AWGM и sing-box запускаются,
аварийные копии на внутренней памяти.

**Шаг 1. Создать туннель правильно.**
`POST /api/singbox/tunnels` со ссылкой
`hy2://<пароль>@177.177.230.47:443/?insecure=1&sni=de-vps.local`.
Проверка: `GET /api/singbox/tunnels` показывает туннель, статус `running`.
Откат: `DELETE /api/singbox/tunnels?tag=…`.

**Шаг 2. Включить NDMS Proxy.**
`POST /api/singbox/ndms-proxy {"enabled":true}`.
Проверка: в Keenetic появился интерфейс `ProxyN`
(`/api/routing/targets` или `show interface`).
Откат: тот же вызов с `false`.

**Шаг 3. Убедиться, что туннель живой.**
`POST /api/singbox/tunnels/test/ip` — AWGM сам скажет, какой внешний IP видит через
туннель. Ожидаем `177.177.230.47`.
Откат: не требуется, это чтение.

**Шаг 4. Доменный маршрут на ProxyN.**
Создать один DNS-список (например `test-youtube`) с доменами YouTube и направить его
на `ProxyN`. Проверка — `explain_route` и реальный запрос с телефона.
Откат: выключить список (`set_dns_route_enabled false`), не удаляя.

**Шаг 5. Проверка на телефоне.**
Телефон **не привязываем**. Он просто пользуется роутером: `2ip.ru` покажет домашний
IP (значит, не завернут), а YouTube пойдёт через туннель (проверяем по счётчикам и
`list_connections`).

**Шаг 6. Расширение.**
Если шаг 5 успешен — переносим остальные списки (Telegram, Discord, AI и т.д.)
на `ProxyN` по одному, с проверкой после каждого.

## 5. Риски и что делаем при них

| Риск | Реакция |
|---|---|
| `ProxyN` не создаётся | пробуем `fakeip-tun`; если и он не даёт интерфейс — возвращаемся к проверенной схеме per-IP |
| Туннель не проходит тест IP | проверяем UDP 443 до сервера, смотрим `sing-box` лог, при неудаче — Hysteria в режиме `tcpRedirect` как раньше |
| Домены идут, но часть сайтов ломается | сужаем список, добавляем исключения |
| Интернет пропал у всех | `POST /api/singbox/router/mode {"mode":"off"}` и отключение списка |

## 6. Чего не делаем

- не привязываем устройства к политикам (это ломает им маршрутизацию);
- не трогаем политику `Hwave`;
- не меняем маршрут по умолчанию;
- не удаляем старые списки — только переключаем цель.
