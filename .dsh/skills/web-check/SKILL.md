# Проверка сайта настоящим браузером

## Два способа

1. **MCP-инструменты `chrome_*`** (основной путь, если они есть в каталоге):
   `chrome_open`, `chrome_net`, `chrome_click`, `chrome_eval`, `chrome_text`.
   Реализованы в `tools/browser_mcp.py` поверх `tools/chrome_cdp.py` — настоящий
   Chrome через DevTools Protocol, без зависимостей. Дают скриншот, сетевую
   сводку (статусы, упавшие запросы), клик и JS.
2. **`tools/webshot.ps1`** (когда MCP-сервер ещё не перезапущен): то же самое,
   но скриншот + DOM из командной строки.

## Зачем это нужно

MCP-браузер **moli** удобен для чтения текста, но для визуальной проверки он
**врёт**: отдаёт кэшированный скриншот (одинаковый `sha256` при разных запросах),
не грузит ленивые картинки (`<img>` с пустым `src`) и показывает «битые» даже те
изображения, которые реально отрисованы.

Настоящий Chrome на этом ПК отрисовывает всё корректно. Проверено 29.10.2026
на `youtube.com`: moli показывал пустые превью, Chrome — полную страницу.

## Инструмент

`tools/webshot.ps1` — запускает установленный Chrome (или Edge) с чистым
профилем, ждёт загрузку и сохраняет скриншот в `.browser/`.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\webshot.ps1 `
  -Url "https://www.youtube.com/@MrBeast/videos" -Wait 25 -KeepDom
```

Параметры:

| Параметр | Смысл |
|---|---|
| `-Url` | адрес страницы (обязателен) |
| `-Wait` | секунд виртуального времени на загрузку, по умолчанию 20 |
| `-Width` / `-Height` | размер окна, по умолчанию 1400×1000 |
| `-KeepDom` | сохранить HTML и посчитать картинки по хостам |

Возвращает: путь к PNG, размер, число `<img>`, число картинок с `src`,
распределение по хостам, путь к HTML.

## Как проверять

1. Запустить скрипт с `-KeepDom`.
2. Открыть скриншот через `read_image` — это единственный честный ответ на
   вопрос «как выглядит страница».
3. Если на скриншоте пусто, а в DOM картинки с `src` есть — смотреть
   **распределение по хостам** и сравнивать с тем, что должно быть.
4. Для проверки одного адреса картинки — `curl.exe -s -o NUL -w "%{http_code} %{size_download}"`.

## Ограничения

- Одна страница за запуск, без кликов и ввода. Для интерактива —
  `mcp__browser__session_start` (CDP на `127.0.0.1:9222`) и Playwright поверх него.
- `--virtual-time-budget` ускоряет таймеры: если страница грузится долго,
  увеличьте `-Wait`.
- Логин не сохраняется: профиль каждый раз новый, поэтому проверяются
  страницы для незалогиненного пользователя.

## Что считать доказательством

Не докладывать «работает» по коду ответа. Порядок силы доказательств:

1. скриншот с видимым содержимым;
2. `curl` с ненулевым `size_download`;
3. DOM с картинками и `src`;
4. HTTP-код.

## Готово, когда

- скриншот открыт через `read_image`, и на нём видно содержимое страницы;
- `chrome_net` не показывает упавших запросов и 4xx/5xx на нужных ресурсах;
- в DOM есть картинки с непустым `src`, и их хосты совпадают с ожидаемыми;
- если проверка не удалась — названа причина и что именно осталось непроверенным;
  «не смотрел» не выдаётся за «работает».
