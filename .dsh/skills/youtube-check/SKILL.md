# Проверка YouTube

## Когда применять

- пользователь жалуется на лаги, тормоза, «крутится»;
- после правки стратегии nfqws2, списков AWGM, маршрутов;
- перед тем как сказать «работает» — вместо ручных скриншотов.

## Инструмент

```powershell
python tools/yt_check.py            # главная + видео + Shorts
python tools/yt_check.py --video    # только видео
python tools/yt_check.py --shorts   # только Shorts
python tools/yt_check.py --json     # машинный вывод
```

Движок — `tools/chrome_cdp.py` (настоящий Chrome через CDP, без зависимостей).
Скриншоты и JSON складываются в `.browser/`.

## Что считается нормой

| Проверка | Метрика | Норма |
|---|---|---|
| Видео | `played` за 10 с | ≥ 5 с |
| Видео | дропнутые кадры | ≤ 5 % |
| Видео | `waiting` (зависания плеера) | ≤ 2 |
| Shorts | `played` на первом и после листания | ≥ 3 с из 8 |
| Shorts | листание | кнопка `Next` сработала |
| Любая | сетевые проблемы | нет `ERR_SSL_*`, `ERR_CERT_*` |

`ERR_ABORTED` в списке проблем — норма (отменённые запросы), на них не смотреть.

## Что означают симптомы

| Симптом | Вероятная причина | Куда смотреть |
|---|---|---|
| `waiting` растёт, `buffered` маленький | канал/CDN не отдаёт данные | `yt-capture.sh` на роутере: ретрансмиты |
| `ERR_SSL_PROTOCOL_ERROR` | desync ломает рукопожатие | стратегия nfqws2, домен в списке |
| `dropped` растёт, `played` нормальный | устройство/декодер, не сеть | не трогать роутер |
| Shorts листаются рывками, видео нормально | много коротких соединений, каждое платит RTT+desync | `yt-capture.sh` + probes |

## Связка с роутером

Когда тест показывает проблему, подтверждать на уровне пакетов:

```sh
# на роутере
/opt/etc/yt-capture.sh 120     # отчёт: ретрансмиты, RST, наши фейки (TTL<=64)
/opt/etc/yt-analyze.sh         # залипшие потоки по conntrack
tail /tmp/mnt/*/keenetic/yt-monitor/probe-*.csv   # RTT до CDN
```

Мониторинг уже работает: демон `S97yt-monitor`, данные на USB, хранение 2 дня.

## Ограничения

- Профиль чистый: проверяется неавторизованный YouTube, персональные ленты и
  подписки не воспроизводятся.
- «Плавность» человеческим глазом не измеряется: смотреть на `dropped`,
  `waiting`, `played`. Если все три в норме, а пользователь видит рывки —
  проблема на клиенте (декодер, расширение, Wi-Fi), а не в сети.
- Shorts на странице бывают в единственном экземпляре: `Shorts в DOM 1 → 1`
  нормально, главное что `after_swipe.played` > 0.
